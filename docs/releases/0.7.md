# goharness 0.7.0

One theme: a `verify` report is about the change, not about the repository it
lands in. On a large codebase one edited file pulls its whole reverse-dependency
closure into scope, and every finding in that closure used to be printed. The
verdict was right and the report was unreadable.

## Two axes on every finding

`state` has always said whether the base revision already carried a finding.
`origin` now says whether it sits in a file the change wrote: `changed`,
`untouched`, or empty where there was no diff to attribute against. They answer
different questions and neither implies the other.

| state | origin | what it is |
|---|---|---|
| `new` | `changed` | the change wrote this defect |
| `new` | `untouched` | the change broke a package it never opened; blocks all the same |
| `preexisting` | `changed` | debt in a file the author is already in |
| `preexisting` | `untouched` | the noise |
| `fixed` | `changed` | the change cleaned this up |

Attribution is at file granularity, from the change set, whose paths were already
module-relative; a finding with no file is placed by its package's directory,
which is what anchors goroutine leaks and test failures. `origin` is decoration
and never enters a fingerprint, so no finding was renamed by its arrival.

## Rendered views

`--evidence` now selects which findings the report carries, in text and in JSON
alike; before this the text report ignored the flag entirely.

| mode | carries |
|---|---|
| `full` | every finding the run produced |
| `diff` | everything blocking, everything new or fixed, debt whose origin is `changed`, and anything unattributed |
| `new` | everything blocking, plus new and fixed |
| `top` | `full`, cut to `--evidence-limit` |

`verify` defaults to `diff`; `audit` and `fast` default to `full`.

**No view ever drops a row whose `blocking` is true.** That is the invariant that
makes a default safe, and `internal/report/scope_test.go` pins it: a filter that
could hide the row that decided the verdict would be a way to be admitted by not
looking. A view changes how much there is to read and never what has to be fixed.
`evidenceScope` names the view, `evidenceOmitted` counts the rows withheld, and
`summary` keeps counting the whole run.

## A move stops introducing what it moved

`git diff --name-status` reports `R100 old new`. The change set discarded the
source and recorded the destination as an addition. A file's path is part of a
finding's identity, so a branch that reorganised code was rejected for every
finding the moved files already carried and credited, in the same report, for
fixing the same ones.

The source path is kept, the base evidence set is realigned into head's
coordinates before the comparison, and the base scope follows renames as well,
since a moved package has no import path at base for head's to be mirrored onto.
`internal/verify/bypass_test.go` carries both halves: a move that also edits the
file still cannot launder the edit past the comparison, and a move on its own
introduces nothing.

## Not computing what provably cancels

A package directory whose judged files are byte-identical at base and head
produces identical findings at both from any check that reads only that
directory. Identical findings carry identical fingerprints, because occurrence
indexes are keyed per rule, file and package rather than globally, so they pair
in the comparison and can be neither new nor fixed. In `verify`, and only where a
base comparison will happen, such a check now examines only the directories the
change touched, on both sides.

Two conditions bound it, each with a case in
`internal/verify/localscope_test.go`:

- the check must read one directory and nothing else, which leaves compilation,
  `go vet`, `go fix`, golangci-lint, the tests, the vulnerability scan and clone
  detection at full scope;
- none of its rules may be ungrandfatherable, because such a rule blocks on a
  pre-existing finding too. The native scan owns every suppression rule and the
  em dash, so the native scan is never narrowed. A `//nolint` in an untouched
  package still rejects the change.

`coverage.localScanNarrowed` and `coverage.localScanPackages` record what was
examined, because an ADMITTED whose scope is invisible is not auditable.

## Compatibility

The report schema stays `goharness.report/v2`: `origin`, `evidenceScope`,
`localScanNarrowed` and `localScanPackages` are additive, and consumers reject
unknown schema identifiers rather than unknown fields. `goharness diff` treats a
scope difference between two reports as a subject mismatch, because two reports
rendered under different views hold different rows of the same run.
