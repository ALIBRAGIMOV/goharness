# goharness 0.9.0

The gate passes on itself again, two routes to an unearned ADMITTED are
closed, and the report says where the time went.

The starting point was the harness's own CI: the 0.7.0 and 0.8.0 workflows
failed at the step "admission gate against itself", INCONCLUSIVE at ten
minutes, with the deadline reported as a tool failure of `go test -race` and
no hint. The local run reproduced it exactly. Nothing in the rules was wrong;
the run cost more than its budget, because the race suite of a repository
whose tests build git fixtures and run the whole pipeline is six minutes on
its own and `verify` ran it twice, once at head and once at base.

## Cost

**The base revision runs a test package only where head's own run of it said
something.** A base test result is consumed by exactly one thing, the
comparison that decides whether a head `GH-TEST-FAIL` or `GH-LEAK-001` row is
pre-existing. A test that passes at head produces no row, so its base result
cannot move a verdict; a failure only the base had would be credit, never a
block. The base test scope is therefore the set of test packages that produced
head test or leak evidence, empty on a clean change, and
`coverage.baseTestPackages` declares it. On this repository the gate's own run
went from 12m48s to 8m47s, and what remains is the head race suite: 7m53s of
the 8m47s is `go test -race` over the harness's own integration tests.

**`DefaultVerifyTimeout` is twenty minutes**, because ten was not enough for
the harness to judge its own release commit on a CI runner even before the base
run was narrowed. A timeout bounds cost and never quality.

**`--jobs N`** binds the scheduler's concurrency limit, which existed and had
no flag. CI runners and shared machines need it.

**The human report names the slowest checks** when a run exceeds a minute, so
nobody has to dig `timing.checksMs` out of the JSON to learn that benchmarks
were seventy percent of the run.

## Trust

**A compiler error is not a kill.** `go test` exits 1 whether a test failed or
the mutated package never compiled, and the near pass stops at the first kill,
so one mutant that did not build discharged the test-effectiveness claim for a
whole change. The overlaid run now reads the `-json` event stream: a package
that did not build is a third outcome beside passed and failed, counted and
never a kill, and a change where no mutant compiled reports `mutation-signal`
unproducible with that reason. `TestBypassUncompilableMutantIsNotAKill` is the
case, red before the fix.

**`verify` scans for vulnerabilities when the change touches dependencies.**
Only `audit` planned the scan, so the command an agent finishes with admitted a
change that pulled a module with a known reachable vulnerability into the build.
A seventh risk domain, `dependency`, is activated by `go.mod`, `go.sum`,
`go.work`, `go.work.sum` and `vendor/modules.txt`; it adds the vulnerability
scan to the security claim, at base as well as head, so a vulnerability the base
already carried is debt and one the change brought in blocks. A code-only change
plans no scan and needs no snapshot.
`TestBypassVulnerableDependencyIsNotAdmittedByVerify` is the case, with
`TestVerifyWithoutADependencyChangeDoesNotScan` and
`TestPreexistingVulnerabilityIsDebtInVerify` as its guards.

**Goroutine-leak evidence has a base side.** The leak detector was injected at
head only, so every leak in the closure compared as new and blocked, including
one in a shared helper the change never opened; the 0.7.0 field report had four
such rows. The base now runs the detector for exactly the packages that leaked
at head, which the narrowed base scope makes affordable. A leak present at both
revisions is pre-existing debt in `verify` and still blocks an `audit`;
`TestLeakPresentAtBaseAndHeadIsPreexisting` pins it, and
`TestLeakedGoroutineRejectsTheChange` remains the guard that a leak the change
introduces is rejected.

**Risk detection reads every changed file.** It was handed only the Go files,
so a rewritten `.sql` migration never activated the persistence domain the
documentation promised it would. `TestSQLMigrationRewriteIsRejected` is the
behaviour that never held before.

**A run deadline is the run's own fault.** A check cut short by `--timeout` was
attributed to the tool it was driving, with no hint, and two releases' worth of
CI reports were misdiagnosed on it. The failure now names goharness, says which
check the deadline cut short, and says what to raise; the worktree guard runs
on its own short deadline after a timeout, so a timed-out run still states the
true worktree state instead of a spurious policy-integrity gap.

## Evidence

**`GH-DEP-001`, advisory and experimental.** Every direct requirement head's
`go.mod` carries that base's did not is reported on the `go.mod` line that
added it. A new dependency is an architecture decision that outlives the change
that made it; the diff shows a line, the finding shows a decision. The reader
is a restricted parser of the two `require` forms the go command writes; a
module dependency to read the file that lists modules would be the decision
this rule exists to make visible.

## Hygiene

**The test suite no longer shares the developer's evidence cache.** Fixture
commits carry a fixed author, committer and date, so the same sources produce
the same commit hash in every run, and a base snapshot cached by one run of the
suite answered for the next one even after the code that produced it changed.
Every fixture now points `GOHARNESS_CACHE` at its own temporary root unless the
case provisioned one first.

**The documents match the code.** `docs/architecture.md` named a report schema
two versions old, a deferred cache package that had long existed under another
name, a govulncheck binary that was never shipped, and a linter discovery order
without the cache. `docs/admission-model.md` and `docs/toolchain.md` now say
which command plans the vulnerability scan and why, and the threat model
carries the two routes closed here as sections 12 and 13.

**A `LICENSE`.** The module had none, so pkg.go.dev refused to render its
documentation. It is MIT; the vendored goleak keeps its own notice.
