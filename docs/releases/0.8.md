# goharness 0.8.0

Every item traces to an event in a field report: goharness 0.7.0 run as the
admission gate for one merge request against a ~1000-package Go monorepo with
heavy legacy debt. Independently established ground truth for that change: it
introduces **zero** lint, vet or go fix findings on the lines it added, fixes
one, deliberately removes two exported types, and regenerates three easyjson
files.

goharness said **REJECTED, 540 blocking rows.**

| what the gate reported | what was true |
|---|---|
| 81 `GO-FIX` rows `new` in changed files | all 81 sit on lines that predate the branch |
| `origin: changed` on 846 rows | those files are not in the diff |
| 429 `preexisting` rows blocking | historical `nolint`, nobody removes them in a merge request |

## Trust

**Base-run paths no longer leak the temporary worktree into fingerprints.**
`repo.AddBaseWorktree` created its worktree under `os.MkdirTemp`, which on macOS
answers `/var/folders/…` while every tool reports the same file as
`/private/var/folders/…`. `target.rel` then computed a path that escaped the tree
and fell back to returning the raw absolute one. Because the file is part of a
finding's identity, base and head never matched, so `go fix` and `go vet` could
not produce a single `preexisting` row: 134 fixed plus 130 new against
golangci-lint's 856 pre-existing on the same files. The temporary directory is
symlink-resolved, `target.rel` absorbs the longest-suffix repair that previously
existed only for golangci-lint and was unreachable, and a `fix.command` no longer
reads `go fix -inline .//private/var/…`.

The invariant is now enforced rather than hoped for: an evidence row whose file
is absolute or escapes the module is a **fault in goharness**, reported through
`failures[]` and leaving its obligations INCONCLUSIVE. A wrong path is a wrong
identity is an unjust rejection, and it must be loud.

`internal/verify/pathhygiene_test.go` carries the fixture that would have caught
it: pre-existing findings from every producer, plus the determinism check that
two runs of one commit agree on every fingerprint. No fixture had ever carried a
pre-existing vet or go fix finding, so both sides produced nothing and always
agreed.

**Volatile text no longer names findings.** `GH-TEST-FAIL` embedded a timestamped
log line and `GH-LEAK-001` the whole goroutine list, whose membership varies per
run, so ten failures and eleven leaks were reported as introduced between two
runs of identical code and one flaky race arrived as `new`, `fixed` and
`preexisting` in a single report. `evidence[].identity` is what a producer states
when it knows its own answer, and the fingerprint uses it instead of the message:
a test failure is its package and top-level test name, a leak is the site it
leaked at, an API break is the symbol. A leak is reported once per site rather
than once per test package that reached it; one leaking helper had produced
thirty-six identical rows.

## The change gate judges the change

**`origin` is an ordered enum, and it is computed correctly.** 0.7.0 tried the
package test for every row instead of only for rows with no file of their own, so
every finding anywhere in a package holding a changed file came out as the
change's. That defect is gone, and the axis it was on is now four values:

| origin | meaning |
|---|---|
| `added-line` | the line falls inside a `+` hunk of base against the verified tree |
| `changed-file` | the file is in the diff, the line predates the change |
| `changed-package` | the package holds a changed file, this file is not one |
| `untouched` | anywhere else in the closure |

`--evidence diff` carries `added-line`, `changed-file`, everything `new` or
`fixed`, everything blocking, and everything the run could not place. Line ranges
come from one `git diff -U0` against the base with no second revision, so the
numbers are the verified tree's, and every path goes through the same
module-relative translation the change set uses.

An audit places nothing. It answers for the repository, and attributing its
findings to whatever commit HEAD sits on would switch off the un-baselineable
core wherever that commit did not reach.

**Ungrandfatherable rules block where the change is.** A pre-existing suppression
now blocks when its origin is `added-line` or `changed-file`, and is reported as
debt otherwise. Every anti-laundering property survives: one the change adds is
`new` and blocks wherever it is, one it leaves in a file it edits blocks, and the
repository is cleaned by the traffic through it. `audit` is unchanged, and the
debt ledger still cannot acknowledge them. On the subject repository this is 463
required violations reduced to the ones the change is actually in.

**Package-level rows are addressable.** `GH-API-001` carried an import path where
a file goes, so ten deliberate API removals arrived with nowhere to click and
nothing to place them against. A removal is now located at the declaration's
position in the base tree, a re-signature at its position now, and
`GH-MNT-002`/`GH-MNT-003` put their package in `package` rather than in `file`.

**Generated code is not compared by function name.** easyjson numbers what it
writes, so deleting one marshalled type renumbers every function after it and
`…Record23` at base is a different decoder from `…Record23` at head: the report
said its complexity rose from 9 to 31. Maintainability deltas and duplication now
pass over files carrying a generated header. A delta between two functions that
are not the same function is not a measurement.

**Remedies address the author of the change.** `goroutine-leak-clean` told a merge
request to add `goleak.VerifyTestMain` to three packages it never opened. A
`TestMain` in a changed package is still an unproducible obligation; anywhere else
it is a repository coverage gap, reported in `coverage`. `GH-POLICY-002` no longer
asserts that a regenerated file was hand-edited, which the harness cannot know.

## Cost and ergonomics

- **Benchmarks run in the changed packages**, not across the closure. 272 seconds
  of a 395 second run went to a package whose benchmarked functions call nothing
  the change touched, and the obligation was activated by a benchmark in a
  changed directory in the first place.
- **`--report FILE`** writes the JSON document to a file and leaves the stream
  for the human report. Editor and agent bridges time out well inside the six
  minutes a monorepo run takes, and redirecting a shell is not available to a
  caller that is not one.
- **`goharness diff` refuses a scope mismatch** with exit 2 unless
  `--allow-scope-mismatch`. It warned and then printed "fixed 5535" where 4795 of
  those rows had merely been omitted by the narrower view. A `state: fixed` row
  of the newer report is also no longer counted as introduced: it describes that
  run's base, not a new finding.
- The human report collapses rows that say the same thing in the same place, with
  a count.
- **The mutation budget covers the change, not its first file.** Sixteen mutants
  were taken in path order, so a nineteen-file branch was measured entirely
  inside its alphabetically first package and said nothing about the other
  eighteen. The budget is now spread across the changed files, one mutant each
  in turn.
- **The near pass stops at the first kill.** One kill is the whole of what the
  mutation claim asks for, and every further near run spent another pass of a
  package's tests to establish something already established.
- **This harness's own parse benchmarks run on a fixed corpus.** They walked the
  module, and the base and head runs of a comparison each walk the tree they
  live in, so what the numbers measured was how much source that revision held.
  The harness reported a ten percent allocation regression on itself against its
  parent commit and the whole of it was ten files that did not exist yet.
- **A benchmark regression needs evidence beyond the measurement spread.** The
  budget is now applied to head's fastest sample against base's slowest, not only
  to the medians with the ranges separated. This harness rejected its own change
  on two benchmarks that measured under one percent apart on an idle machine:
  head's samples had been stretched by the base tree's test suite running beside
  them, which separates two ranges describing identical code. A real regression of
  about the size of the budget now goes unreported when the samples are spread,
  which is the right way round.

## Compatibility

The report schema stays `goharness.report/v2`; `identity` is additive and
`origin` gained values.

`identity` and the located package rows move the fingerprints of `GH-TEST-FAIL`,
`GH-LEAK-001`, `GH-API-001`, `GH-MNT-002` and `GH-MNT-003`. Existing
`goharness.debt.yaml` entries for those rules stop matching and have to be
re-recorded with `goharness audit --baseline`. That is the price of those
identities having been wrong.

`--baseline` left the front-page flag list; it belongs to `audit` alone and
`goharness help audit` documents the ledger in full.
