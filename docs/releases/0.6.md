# goharness 0.6.0

Every item below traces to a defect found by running 0.5.0 over a repository
whose module sits in a subdirectory of the git root, audited from two working
directories.

## Trust fixes

**D1. One coordinate system for change paths.** `internal/change` collected
paths from `git diff --name-status` (repository-relative) and `git ls-files
--others` (cwd-relative) into one slice, and everything downstream joined them
onto the module root. Paths are now normalised once at ingestion, against the
module prefix that `git rev-parse --show-prefix` reports. Three shipped
mechanisms were silently disabled by the old behaviour and work again where the
module is not the git root: `isPolicyFile` (GH-POLICY-001 did not fire in any
monorepo), `partitionGenerated` (a changed generated file was exempted instead
of judged), and `graph.SeedPackages` (verify scope was empty and every check ran
vacuously). Changed files the module does not contain are reported as
`change.outsideModule` rather than dropped.

**D2. Invocation-invariant vulnerability evidence.** x/vuln resolved the Go
version for standard-library findings by running `exec.Command("go", "env",
"GOVERSION")` with no `Dir` and no `Env`, in the harness's own working
directory under the operator's raw environment. Two audits of the same commit
minutes apart reported 0 and 17 reachable standard-library vulnerabilities. The
version is now resolved through `tool.Runner` with `Dir` at the module root and
`VerificationEnv`, passed explicitly to the scanner, recorded as
`versions.goStdlib`, and included in the base-evidence cache key. Where the host
toolchain is older than the module's `toolchain` directive, the scan is judging
a configuration the repository forbids: security goes INCONCLUSIVE naming both
versions, in `verify` and in `doctor`.

**D3. A tool fault is never phrased as a code fact.** "1 changed Go file was
compiled by nothing in this run" was a false statement about the repository
produced by a path the harness failed to resolve. Deliberate toolchain exclusion
stays `Unexamined`; an unresolvable path is a distinct value that becomes a
`CheckFailure` attributed to `goharness`, with the unproducible reason pointing
at `failures[]`.

**D4. The canonical bounded pool is bounded.** GH-CONC-002 inspected only a
spawn loop's body for a semaphore or token channel and never its own iteration
bound, so `for range workerCount { go w.run(ctx) }` was reported as unbounded
and adding a redundant semaphore would have silenced it. The bound is now
consulted first: literal, named constant, or struct or config field. A variable
bound stays reportable at advisory severity. False-positive rate in the field
audit was 2 of 2.

**D5. Package-scoped evidence carries an anchor.** GH-LEAK-001 arrived with
`file: null`, so no exception could reach it and remediation began with a manual
hunt. goleak's origin stack head is surfaced and the package directory is set as
the file anchor. The policy hole this exposed is closed too: `scopeMatches`
returned false on an empty file, making package-scoped findings unreachable by
any scoped exception, and now matches on `Evidence.Package` when `File` is empty.

**D6. Pack coherence on proven-safe encodes.** errchkjson proves certain
`json.Marshal` calls cannot fail and flags an error check on them; the strict
pack's errcheck flags the discard. Rather than add a linter and manufacture the
contradiction, the canonical escape (a typed helper that owns the check once) is
documented in `docs/admission-model.md` and shipped through the compliant-pattern
section of `goharness explain`.

**Test infrastructure.** Five of the six defects were invisible to a suite that
built one repository layout and ran from one directory. `internal/verify` now
runs its acceptance and bypass suites under a layout matrix over {module at git
root, module in a subdirectory} x {cwd at git root, cwd at module dir} x {--dir
given, defaulted}, plus invocation invariance as a property (byte-identical
`DeterministicJSON` from two working directories) and a hostile-environment
guard (`GOFLAGS`, `GOTOOLCHAIN`, foreign cwd, report unchanged).
`TestMandatoryCoreDoesNotShrink` lists `MandatoryRuleIDs` and
`UngrandfatherableRuleIDs` literally and fails if either loses a member.

## Signal shape

In the field audit, 98.7% of blocking volume came from two mechanical rules and
nearly all engineering signal lived in the remaining 1.3%. The claims model
rescued the verdict; the document carried no ordering.

- **Consequence classes.** Every rule in the registry carries one of
  `silent-loss`, `unsafe-behavior`, `structural`, `hygiene`. `evidence[]` is
  ordered by it, so a consumer that allocates effort by position meets the
  silent data loss before the typography. A registry test keeps the mapping
  total.
- **Remedy classes.** For unchecked errors the callee decides the fix, and the
  message names it. Each finding carries a `remedyClass` of resource-close,
  domain-write, cleanup or diagnostic, which turned 461 rows into six decisions
  and separated 30 discarded compliance audit-trail writes from 44 `rows.Close`.
- **`summary`.** Counts per rule, file, consequence, dimension and remedy class,
  with the blocking/advisory and new/pre-existing/fixed splits. Computed over
  the whole evidence set, so a truncated rendering still reports the run's
  totals.
- **`goharness fix --rule <ID>`.** The mechanical remediation for the rules
  whose fix can be stated exactly, with `--dry-run`. Rewrites work on parsed
  syntax, so string literals are untouched by construction. Findings carry
  `fix.command`. It is a write command: no verification command reaches it.
- **The debt ledger.** `goharness audit --baseline` records blocking findings as
  acknowledged debt in `goharness.debt.yaml`; later audits enforce no new debt
  and report burn-down and baseline age in a `baseline` block. Only the copy
  committed at HEAD counts, the ungrandfatherable core is never recorded, and
  editing the file is GH-POLICY-001 like any other edit to the gate.
- **`policyShadow`.** An audit reads the repository's own `.golangci.yml`, diffs
  it against the strict pack, and attributes this run's findings to each
  mechanism it finds. A report section, never a claim: it does not touch a
  verdict, a count, or an exit code.
- **`coverage`.** Packages in scope, files judged, files exempted as generated
  (named), test packages run, and test packages where leak injection was blocked
  by an existing TestMain. An ADMITTED whose scope is invisible cannot be
  audited.
- **`--evidence top`.** Keeps `summary` plus the highest-consequence findings and
  sets `evidenceTruncated` with `evidenceOmitted: N`. Truncation is always
  declared. `goharness explain FINGERPRINT --report r.json` resolves any omitted
  row.
- **`goharness explain`** accepts a fingerprint as well as a rule ID, and prints
  a compliant pattern for remediation-shaped rules.
- **`goharness diff OLD.json NEW.json`** compares two reports on fingerprint
  identity: fixed, introduced and remaining, split blocking from advisory,
  grouped by consequence class then rule, with the verdict transition and every
  claim that moved. A pure function over two documents: no git, no cache, no
  filesystem walk beyond reading the two files. Exit 0 when nothing blocking was
  introduced, 1 when it was, 2 when a report could not be read. These are not
  the verification exit codes.

## Performance

The tool is used inside an agent repair loop, where one repository is verified
ten to fifty times with small edits. No item below changes a byte of the
deterministic report; the determinism tests are the gate.

- **P3, one parse per file.** `Scan`, `ComputeMetrics` and `CloneFindings` each
  called `parseUnits` independently, so every judged file was read and parsed
  three times. They now share one pass that walks each package directory once.
  `BenchmarkSeparateParses` against `BenchmarkSharedParse` over this repository:
  **2.27x faster**, with peak memory falling from the whole corpus to one
  package.
- **P5, head-side incremental evidence.** Native formatting findings are a pure
  function of (file content, options, goharness version), keyed per package in
  the existing derived store with a per-entry integrity hash. Steady-state
  goimports over an unchanged tree: **7 ms**. End to end, a repair loop that
  edits two files of a thousand: **33% less wall-clock**. `--no-cache` reaches
  the same verdict, and a determinism test asserts cached and uncached runs are
  byte-identical.
- **P2, `NeedDeps` dropped from the package graph load.** It populated a package
  for every transitive import including the whole standard library, and the only
  consumer of `p.Imports` builds a reverse index restricted to root packages.
  This load runs twice per verify, head and base.
- **P4, duplication computed once.** golangci `dupl` and the native
  `CloneFindings` answered the same question with two full passes and two sets
  of advisory rows.
- **P1, weighted semaphore: tried and reverted.** Charging the core-saturating
  subprocesses (build, vet, test, golangci-lint, the vulnerability scan) half
  the concurrency limit each, so at most two overlap, made an audit **14%
  slower** and a verify **16% slower** on a forty-package module. None of those
  tools is parallel enough to fill the machine alone, so overlapping their
  serial phases beats protecting them from each other. Every check still
  acquires weight 1, and `engine.go` records the measurement so the next reader
  does not repeat it.

## Report schema

`goharness.report/v2` stands. Every addition is additive and every new block is
either always present or omitted entirely when it does not apply:

- `summary`, `coverage`: always present.
- `baseline`: present only in an audit that read a committed ledger.
- `policyShadow`: present only in an audit of a repository with its own
  golangci configuration.
- `versions.goStdlib`, `change.outsideModule`: always present.
- `evidence[].consequence`, `evidence[].remedyClass`, `evidence[].fix`: per
  finding, omitted when empty.
- `evidenceTruncated`, `evidenceOmitted`: always present; false and 0 in a full
  rendering.

`goharness.diff/v1` is a new schema, versioned from birth. It is not a report
and must not be read as one.

## Fingerprint churn

**GH-LEAK-001 fingerprints changed.** The rule now carries a file anchor (the
package directory), and the file is part of the fingerprint. A GH-LEAK-001
finding recorded in a 0.5 debt ledger will not match its 0.6 identity and will
be counted as new. The change lands before the ledger exists in a released
version, so no recorded baseline in the wild is invalidated; a repository that
carried one from a pre-release build re-records it with
`goharness audit --baseline`.

No other rule's identity moved. Consequence and remedy classes are not part of
the fingerprint, deliberately: a rule's class is a presentation decision, and
letting it into the identity would rename every repeated finding whenever a
class was corrected.

## One behavioural removal

**`GCL-dupl` no longer runs.** It stays in the registry so an old report's rows
still explain, but duplication is now reported only by `GH-DUP-001`, the native
check this project controls and can explain. Both answered the same question,
at the cost of two full passes and two sets of advisory rows on one duplication.
Repositories that filtered on `GCL-dupl` will see those findings under
`GH-DUP-001` instead.

## Documentation

- `docs/threat-model.md`: the routes by which a change could reach ADMITTED
  without the evidence, the mechanism closing each, the test that pins it, and
  the residual risk. It doubles as the review artifact for
  `internal/verify/bypass_test.go`.
- `docs/agent-contract.md`: a copy-pasteable CLAUDE.md/AGENTS.md fragment.
- `docs/adopting-alongside-golangci.md`: adopting the gate in a repository that
  already runs its own golangci-lint configuration, including the couplings that
  break the incumbent gate if the two are adopted in the wrong order.

## Deferred to 0.7

Runtime probes beyond goroutine leaks: file-descriptor and socket leaks,
flakiness detection, and fuzz-smoke for decoders of external input. New rule
machinery enters advisory and experimental and is promoted on corpus evidence;
that calibration is the gating work, not the implementation.
